# July 2026 Update

Release versions: `0.1.0`, `0.1.1`

Release date: `07/30/2026`

## Changelog

This is the release where plugins stop being a black box. Commands can now declare their settings as a typed schema, hosts can generate real configuration forms from it, and the free-form argument string is gone in favor of a typed argument bag. This is the SDK release that powers the DeckSurf app for Windows.

### Command parameter schema

Plugins describe their settings declaratively and hosts render whatever UI fits:

- [`CommandParameterAttribute`](xref:DeckSurf.SDK.Models.CommandParameterAttribute) declares a parameter on a command class: key, type, display name, description, default, choices, numeric range, and ordering. Attribute-based, so hosts read schemas from types without instantiating commands.
- [`CommandParameterType`](xref:DeckSurf.SDK.Models.CommandParameterType) covers `String`, `Integer`, `Boolean`, `Choice`, `FilePath`, `FolderPath`, `ImagePath`, and `Secret` (masked input). A duration is just an integer with a range, so there is no separate duration type.
- [`CommandSchemaReader`](xref:DeckSurf.SDK.Util.CommandSchemaReader) reads a command's declared parameters, sorted and deduplicated.
- [`CommandParameterValidator`](xref:DeckSurf.SDK.Util.CommandParameterValidator) validates a set of values against a schema: required fields, integer ranges, choice membership.

### Typed command arguments

- [`CommandArguments`](xref:DeckSurf.SDK.Models.CommandArguments) replaces the old `k=v` argument string: a case-insensitive key/value bag with typed getters (`GetString`, `GetInt32`, `GetBoolean`).
- [`CommandArgumentsJsonConverter`](xref:DeckSurf.SDK.Models.CommandArgumentsJsonConverter) stores arguments in profile JSON as an object, and still reads the legacy string form, so existing profiles load unchanged.
- `CommandArgumentParser` is gone. If you parsed arguments by hand, take the values from [`CommandMapping.CommandArguments`](xref:DeckSurf.SDK.Models.CommandMapping) instead.

### Runtime-served choices and command health

Two optional interfaces let commands talk back to the host while a profile is being edited:

- [`IDeckSurfChoiceProvider`](xref:DeckSurf.SDK.Interfaces.IDeckSurfChoiceProvider) serves live suggestions for a parameter, for example the scene list of a running OBS instance.
- [`IDeckSurfStatusProvider`](xref:DeckSurf.SDK.Interfaces.IDeckSurfStatusProvider) reports command health as a [`CommandStatus`](xref:DeckSurf.SDK.Models.CommandStatus), so a host can show whether the thing a command depends on is reachable.

### Mapping targets, touch keys, and backlight colors

- [`MappingTarget`](xref:DeckSurf.SDK.Models.MappingTarget) binds a [`CommandMapping`](xref:DeckSurf.SDK.Models.CommandMapping) to a specific piece of hardware: `Key`, `Knob`, `Screen`, or `TouchButton`. Old profiles without a target keep working as key mappings.
- `TouchButton` covers the two touch keys flanking the Stream Deck Neo screen. Their backlight is driven through `SetKeyColor` at an index offset by `ButtonCount`.
- `CommandMapping.ButtonColor` (added in `0.1.1`) carries an optional backlight color for touch key mappings, stored in profile JSON as a `#RRGGBB` string through [`DeviceColorJsonConverter`](xref:DeckSurf.SDK.Models.DeviceColorJsonConverter).

### Plugin loading in the SDK

- [`PluginLoader`](xref:DeckSurf.SDK.Core.PluginLoader) moves plugin discovery into the SDK: scan a directory for plugin assemblies, load compatible commands for a device model, or read command types without instantiating anything.
- [`PluginMetadata`](xref:DeckSurf.SDK.Models.PluginMetadata) gains a display `Name`.
- [`CommandIconAttribute`](xref:DeckSurf.SDK.Models.CommandIconAttribute) lets a command declare its icon file; hosts render only developer-declared art.
- [`CommandDynamicDisplayAttribute`](xref:DeckSurf.SDK.Models.CommandDynamicDisplayAttribute) marks commands that draw their own key face, so hosts know not to offer a static image.

### Live frame events

- [`ConnectedDevice`](xref:DeckSurf.SDK.Models.ConnectedDevice) raises `KeyImageSet` and `ScreenImageSet` whenever an image is written to the hardware, with the pre-encoding bytes. This is what live key previews in a host UI are built on.
- `SetScreen` became a template method with per-device cores, and `KnobCount` is exposed on the device.
- Fixed the Stream Deck Plus rendering images upside down: its panel mounts upright, unlike the other models.

### Profile management

- [`ConfigurationHelper`](xref:DeckSurf.SDK.Util.ConfigurationHelper) gains `GetProfilesRootPath`, `ListProfiles`, `SaveProfile`, and `DeleteProfile`.
- Profile names validate against a fixed, platform-independent character set, so a profile created on Linux can always round-trip to a Windows machine.

### Breaking changes

| Gone | Use instead |
|---|---|
| `CommandArgumentParser` | [`CommandArguments`](xref:DeckSurf.SDK.Models.CommandArguments) on the mapping |
| `CommandMapping.CommandArguments` as `string` | Typed [`CommandArguments`](xref:DeckSurf.SDK.Models.CommandArguments); legacy strings still deserialize |
| `CommandParameterType.DurationSeconds` | `CommandParameterType.Integer` with `MinValue`/`MaxValue` |

### Tests

The suite grew from 412 to **490 tests**, now also covering the schema reader, the validator, typed arguments and their JSON converter, profile management, plugin loading, mapping targets, command status, and the device color converter. The suite runs on Linux in CI, which is how the platform-dependent profile name validation got caught.

## Installing package

You can see the package [on NuGet](https://www.nuget.org/packages/DeckSurf.SDK/).

```powershell
Install-Package DeckSurf.SDK -Version 0.1.1
```
